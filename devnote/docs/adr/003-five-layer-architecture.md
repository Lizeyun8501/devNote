# ADR 003: 五层解耦架构

| 属性 | 值 |
|------|------|
| **标题** | 采用五层解耦架构设计 |
| **状态** | Accepted |
| **日期** | 2025-02-01 |
| **决策者** | DevNote 核心架构团队 |

## 上下文

DevNote 是一个功能丰富的笔记应用，涵盖编辑器、同步、加密、知识图谱、闪卡、画布、插件等多个子系统。需要一个清晰的架构来管理复杂性、支持独立演进、并保证可测试性。

### 设计约束

1. **本地优先**：核心功能离线可用，网络仅用于同步。
2. **跨平台**：同一份核心逻辑在桌面和移动端复用。
3. **可扩展**：支持 WASM 插件扩展功能。
4. **可测试**：各层可独立测试，不依赖外部资源。

## 决策

采用**五层解耦架构**，每层有明确的职责和接口边界：

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1: 表示层 (Presentation)                          │
│   Flutter UI + BLoC 状态管理 + 路由 + 主题               │
│   技术: Dart / Flutter / flutter_bloc / go_router       │
└─────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────────────────────────────────────┐
│ Layer 2: 桥接层 (Bridge)                                │
│   FFI 调用封装 + 请求路由 + 序列化/反序列化               │
│   技术: Dart ffi / C ABI / JSON                         │
└─────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────────────────────────────────────┐
│ Layer 3: 核心层 (Core)                                  │
│   领域模型 + 业务逻辑 + CRDT + 加密 + 搜索 + 图谱         │
│   技术: Rust (19 crates)                                │
└─────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────────────────────────────────────┐
│ Layer 4: 持久化层 (Persistence)                         │
│   SQLite 本地存储 + Schema 管理 + 迁移                    │
│   技术: rusqlite (Rust) / sqflite (Dart)                │
└─────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────────────────────────────────────┐
│ Layer 5: 服务层 (Services)                              │
│   Go 同步服务 + 业务服务 + 对象存储                       │
│   技术: Go / Gin / gRPC / WebSocket / MinIO             │
└─────────────────────────────────────────────────────────┘
```

### 各层职责

| 层级 | 职责 | 不允许做的事 |
|------|------|-------------|
| **L1 表示层** | UI 渲染、用户交互、状态管理、路由导航 | 直接访问数据库、执行加密操作、处理同步逻辑 |
| **L2 桥接层** | 跨语言调用封装、请求分发、错误转换 | 包含业务逻辑、持久化操作 |
| **L3 核心层** | 领域模型、业务规则、CRDT 合并、加密、搜索 | 直接渲染 UI、直接操作 HTTP 响应 |
| **L4 持久化层** | 数据存取、Schema 管理、事务控制 | 包含业务规则、网络通信 |
| **L5 服务层** | 远程同步、认证授权、对象存储、API 网关 | 本地数据存储、UI 渲染 |

### 依赖方向

```
L1 → L2 → L3 → L4
            ↕
           L5 (双向: gRPC/WebSocket 通信)
```

上层可以调用下层，下层不能调用上层。L3 核心层与 L5 服务层通过 gRPC/WebSocket 协议双向通信，但保持逻辑解耦。

## 后果

### 正面

- **关注点分离**：每层职责单一，降低认知负荷，新成员可快速理解各自领域。
- **独立测试**：核心层（Rust）可脱离 UI 独立进行单元测试；持久化层可使用内存 SQLite 测试。
- **可替换性**：表示层可替换为其他 UI 框架（如 Qt、Web），只要桥接层接口不变。
- **并行开发**：多层可并行开发，通过接口契约协调。
- **本地优先**：L1-L4 离线完整可用，L5 仅在联网时启用。

### 负面

- **过度工程风险**：对于简单功能，跨多层调用可能显得繁琐。
- **调试链路长**：一个请求从 UI → FFI → Rust → SQLite → 返回，问题定位需要跨语言和跨层追踪。
- **数据双源真理风险**：Dart 端（sqflite）和 Rust 端（rusqlite）可能各自维护 SQLite，导致数据不一致。**需要确保 Rust 是唯一数据源。**

### 已识别风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 数据双源真理 | 废弃 Dart sqflite，统一使用 Rust rusqlite 作为唯一持久化层 |
| 调试复杂 | 建立统一日志链路（tracing + OpenTelemetry），每个请求有唯一 trace_id |
| 层间过度通信 | 在桥接层实现请求批处理，减少 FFI 调用次数 |
